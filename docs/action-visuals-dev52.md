## 特效发现与处理

### 焰魔

原生 `Ignis_Renderer.render` 只更新 `socketPosArray[0]`；真正的剑刃火焰由实体 `tick` 调用私有 `SwingParticles`，后者含完整原生时间窗，再调用 `Flameswing`。先前视觉代理不执行 Boss tick，因此只渲染模型不能带出火焰拖尾。

本版在原生 renderer 更新剑尖后，调用这个纯视觉方法；复用原生火焰／灵魂火焰、密度和动作窗口，不运行整只 Boss 的 `tick` 或 `aiStep`。新动作、切换阶段、丢失采样或瞬移后先初始化前一剑尖位置，避免从零坐标或旧位置产生极长粒子线。采样按客户端逻辑 tick 和变化的动画进度去重，不能随帧率重复生成。

另外补接强化腾空砸击的 `PatternParticle`、强化落地收招的 `Sphereparticle`、剑舞第二段收尾的 `StrikeParticle`。原有服务端冲击／落地粒子仍保留。当前本体的另一个方法 `SwingParticle` 实际没有发出粒子，不能把“存在调用名”误认为本体有独立刀光；本版没有补造不存在的原生斩击贴图。

### 咒翼灵骸

原生 `Maledictus_Cicle_Layer` 已包含双段旋斩、连击、上挑、腾空等动作的手部圆环与电弧，现有 native renderer 会执行这些层。真正影响可见度的是统一 `PhantomBuffers` 把它们也乘上了第一人称 0.10 的模型透明度。

现在纹理位于 `textures/particle/` 的动作层，以及无纹理的电弧层，使用独立的特效透明度。默认模型仍是第三人称 0.28、第一人称 0.10；特效默认 0.80／0.65，可在客户端配置的 `[action_phantoms] effect_opacity`、`first_person_effect_opacity` 调整。不会修改已有身体透明度选择。

原生冲刺／腾空的 `AfterImageParticle` 通过真实实体 ID 获取 Boss，未注册视觉代理无法直接提供这个 ID。本版复用已有原生模型及渲染层，绘制短暂的历史姿态和位置，最长五 tick；仍跟随自身／友军／位置执行的同一组同步数据。残像沿用较低透明度并快速淡出，不会把每个残像的手部光环再放大到 0.80。没有世界实体、虚构 ID、额外伤害或服务端 AI。与原生残像的区别是保留采样时姿态，而非查询真实 Boss 的当前姿态。

双段旋斩原生没有独立的长刀光／武器火焰粒子方法，主要表现就是武器动画、手部环和电弧；不把冲刺的残像无差别套到所有近战动作上。

### 其他已核对的接线

- 斯库拉挥锚已使用原生 `ScyllaSwingParticleOptions` 和旋风；位置执行沿用 `PositionStormParticle`，不是传入无效实体 ID。
- 末影守卫体术已发送冲击、末影粒子，原生符文／子弹实体独立同步；先驱者激光、导弹、烟云与巨兽落地／焰柱仍走既有原生载荷及粒子传输。
- 本轮没有发现需要修改这些载荷接线的新证据；这不代表客户端画面已逐项人工验收。
