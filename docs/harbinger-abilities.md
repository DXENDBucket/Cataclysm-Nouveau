# 先驱者：下一系列静态审计

2026-10-12；依据实际 Cataclysm 1.21.1-3.33 JAR。当前附属 dev.16，尚无先驱者系列魔符。这是候选和实现边界，未新增注册、配方或战斗代码。

原生 JAR SHA-256：`371956d0c2e3b56729ee93b955e936875d210e372fe734cdb74326d89ef79875`。原始反编译输出仅放仓库外的临时审计目录，不复制原生实现或素材进仓库。

## 已发现的关键边界

- 原生激光弹、导弹继承 AbstractHurtingProjectile，而已有 NativePayloads 的部分入口限定 ThrowableProjectile。应在附属侧调整载荷创建与命中接口的类型边界；不能为了套旧入口重新实现半份原生弹体。Core 现有实体载荷 API 不要求把它们变成 ThrowableProjectile。
- 原生导弹击杀回调包含两次治疗：先 5，再 Boss 的 LifeSteal 或普通施法者分支的 5。当前默认可能合计 10；制作时需明确玩家侧规则，不能遗漏后宣称完整复用。
- 烟云原生每 5 tick 检查 3 点伤害并施加凋零 I，具有独立半径、预热和逐渐收缩；无敌帧会影响实际输出，不按检查次数直接乘成 DPS。
- 死亡激光基础伤害还加有上限的血量项。该实体实际计算会把 hpDamage 再乘 0.01，不能仅凭配置默认 0.05 将它写成 5% 最大生命。
- 原生死亡激光会处理玻璃、EMP 以及可选点火；玩家侧应遵守当前附属的默认地形边界，普通 Boss 不受联动 opt-in 修改影响。
- 激光实体同步 caster ID、角度、时长；原生客户端又直接读取 caster 头部朝向。位置触发和其他生物触发必须同时核对两端，不能只测试 hurt 成功。
- 导弹爆炸应显式进入 Conflux NativeSpellDamage 同步作用域，直接命中和子云使用同一个原始上下文；不能给百分比项、子攻击重复加成。药水凋零后续 tick 不自动接入。
- 实际 executor、damageOwner 与 payer 保持分离，复用 Core Allies；原生只检查 isAlliedTo 不代表已经涵盖所有跨模组友军。
- 武器图标模型需检查原生 item renderer，避免再次出现仅引用 builtin/entity 却无真实物品身份的空图标。

## 获取材料预算

原生先驱者每次必掉 1 个凋灵合金块，原生配方拆成 9 锭。唱片只有约 10% 概率，不用作整套必需材料。

激光加特林与凋灵突击肩炮各消耗 2 锭；若用武器制作某个魔符，这两锭必须计入全套预算，不能当作免费来源。图标和制作耗材仍可分开。

初步建议：两项综合较强的能力使用 2 锭，其余使用 1 锭；五项约 7 锭，加独立烟云约 8 锭，单次击杀足够。若再保留两把原生武器，则合计 11–12 锭，通常两次击杀足够。这仅是分配候选，正式新增或改配方前再核对；保留用户 1–3 次击杀可学齐的原则。

## 后续验证范围

制作后一次性覆盖原生直击与爆炸来源、点燃/凋零、击杀治疗、抛物线与追踪、子云归属/友军、重复载荷付费、空蓝与创造、死亡激光两端姿态、结束/死亡/换维度/卸载清理，以及最终包资源隔离。费用按含爆炸和状态的总输出估算，并参考 Iron 可达高等级，不能只按等级 1 比较。

本轮只有静态研究，无客户端或服务器启动；尚未确定 Mana、冷却与具体魔符 ID，没有制作新的 JAR。
