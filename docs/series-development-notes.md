## 整套能力的获取原则

用户明确：后续灾变 Boss 通常击杀 **1–3 次即可获得全部能力**。默认按单名玩家制作并学习每种魔符各一次计算；多人分别学习、补做重复魔符的额外消耗另计。

- 先汇总整套配方需要的 Boss 材料，再与实际发布 JAR 的掉落表对照。间接制作材料所需的 Boss 掉落也算入总量，不能只看每个魔符的独立配方。
- 少量核心、综合强度高的能力使用数量少的标志性掉落；其他能力优先采用数量较多的掉落。物品能力适合时可以使用对应 Boss 武器。图标与配方材料可独立选择。
- 判断随机掉落时考虑通常获得的数量与概率，避免低概率素材成为学齐整套的隐性长期刷取门槛。新增能力后重新核对总需求。
- 魔源宝石、经验等正常制作成本可以保留。原生 Boss 掉落不需为每个新增魔符改动；材料分配优先服务整套获取目标。

dev.10 巨兽示例：两种犄角配方、一种锻锤配方、七种电池配方。原生每次掉一个犄角、一个锻锤和 16–24 个电池，因此两次击杀足够制作整套十种能力，且还可保留一把锻锤使用。

## 新 agent 必须获得的判断依据

- 原模组完整实现优先于只复刻一次伤害。查服务端入口，同时查同步、实体事件、渲染器、粒子、声音、命中后子效果与结束过程。
- 同类能力优先 Boss 版本；没有物品施法来源时可以采用 Boss 直接掉落物制作。不要机械地把只适合 Boss 身体的动作、防护或地形破坏全部做成魔符。
- 区分施法者、执行者、受益目标和付款者。友军执行冲锋并不意味着由友军支付；所有者/伤害归属用 Core 上下文，友军用 Core API。
- 原生轨迹和 Ars 轨迹只保留一个运动驱动者。普通、持续/重复载荷分别检查命中次数、费用和接续次数；子攻击属于已付费用时不要再次收费，也不要各自复制整段 Ars 后续效果。
- 临时修改世界必须覆盖自然结束、所有者离开、区块卸载、重启及位置被替换；不能只在实体正常死亡时清理。
- 新状态能力说明清楚默认时长、修饰公式、上限和保护范围。不要给共享形态写某一种载荷专用的增强说明。
- 图标父模型可能是 builtin/entity，必须检查真实物品身份和原生渲染入口。文本要核对 Ars 实际使用的 glyph_name 与增强说明键。
- 费用结合命中覆盖、持续攻击、控制及组合能力评估；Iron 的对照等级不能始终假定为 1。参考相邻 Ars-Balance-Baselines 的当前记录，尚未实际测到的数据应标为估算。
- 收拢修改后做必要验证。GameTest 不能证明客户端画面完整；既有成功记录不能替代新代码的检查。固定 Core 副本不改，公共修复另开明确的 Core 任务。

## dev.14 动作核对经验

把 Boss 动作转成友军增益时，付款者、伤害拥有者与运动执行者应分开；需要按实际执行者阻止重复动作。原生内部攻击方法可能直接构造 mobAttack(Boss)，即使子实体已重绑 owner，近战仍需单独改归属。旋风原生推力不自动排除友军，需要 opt-in 过滤，不能改变本体 Boss 的规则。

多目标 Mixin 的 @Shadow 需要显式 remap=false；类级 remap=false 不能替代此处的核对。GameTest 计数必须区分主攻击和火花落地等子攻击；同一落地雷暴有 35 道主落雷，不能把两枚火花产生的落雷视为额外重复执行。瞬态 Boss 的服务器帧不会自动产生客户端粒子，仍要显式发送原生资源。

## dev.20：组合攻击与数值修饰

完整原生goal可能包含多次齐射，必须逐一核对发射tick及每次数量；先驱者榴弹是两轮5/7，不是总量5/7。脱离世界的Boss调用帧需要校准炮口高度，所有子实体重绑真实伤害拥有者，并有自己的生命周期；子攻击不自动重复收费或执行后续编排。脱离世界的Boss不能广播自己的动画ID，可捕获原生动画请求安排连续动作。

## dev.37：身体行动幻影推广

原生动画有两种机制：守卫/先驱者的 Lionfish Animation 与斯库拉/巨兽的 AnimationState。后者不能只同步 attackTicks；未 tick 的客户端渲染代理必须启动对应动画，并按服务器进度重建时钟，否则姿态静止或不断从头播放。视觉层不得运行 Boss aiStep、攻击或生成真实 Boss。

新增阶段同步应立即发送动画切换/重置，保持原生半血和冲锋标记。结束包在 goal.stop 之前发送；原生 tick 提前清空动画时应使用最后有效姿态关闭，避免只能等客户端租期自然过期。第一人称更透明对应降低 opacity，此次由0.14降至0.10。详情见[身体行动幻影扩展](body-action-phantoms-dev37.md)。

## dev.38：视觉锚点与执行锚点必须同时接入

增加幻影并不等于原执行入口支持位置。dev.37遗漏位置执行后，用户指出与焰魔不一致：旧动作有的拒绝方块目标，有的把它转成施法者移动。修正应同时接入Core位置锚点、原生服务端攻击和客户端位置元数据，不能仅在客户端画一个模型。

固定点没有实际执行者，不能用付款者补成executor，也不能取得其身体声明。原生移动/传送Goal可以生成冲量，但位置调用帧必须复位；跃落需明确固定点的准备/打击阶段，不能等待一个不存在的身体落地。测试应证明远处敌人实际受伤、保护友军且施法者运动/重力不变。详见[dev.38说明](position-body-actions-dev38.md)。

## dev.39：执行身份不应成为两套方向实现

友军增益/执行资格用Core的caster-based beneficial锚点，不能把未通过资格的敌方目标回退为施法者，也不能把damageOwner用于授权。共享ActionGeometry读取实际actor的视角/目标，自身/友军不分支。

原生Goal.start/tick都可能覆盖姿态；第一次发包前也要校正，先驱者调用帧构造器默认读取caster方向，不能以为传入了actor位置就已得到actor朝向。纯垂直视角的水平fallback也必须是actor自己的yaw。数值角度比较允许浮点容差，不以Float.equals判断几何是否一致。详情见[dev.39](beneficial-steering-dev39.md)。

## dev.43：位置动作的粒子并不自动来自幻影

用户发现固定位置旋转挥锚缺少特效。位置分支原先只有通用冲击粒子，漏了 ScyllaSwingParticleOptions 和 StormParticleOptions；两种动作路径现共用原生弧光／连段／落地发送逻辑。实装 3.33 StormParticle.tick 在 getFromEntity 为 null 时会 remove，传 -1 不能直接实现固定点旋风；附属仅扩展原生粒子的位置采样，用从不加入世界、不 tick／渲染的客户端视觉锚点保持原生拖尾、材质、旋转、淡出与到期。它不承担执行、伤害、收费或友军身份。服务端粒子包检查不等于客户端画面已验收。


## dev.44：咒翼怒气是跨次施法状态

用户选择主动获得和原生近战命中获得两条入口。首批只有幽灵箭／幻影戟／怒气魔符，未做咒翼近战，不能宣称近战获取已经可玩，也不能为了补入口给所有普通攻击擅加怒气。`MaledictusRage.gain/consume/clear`供后续原生能力适配共享；增层仅在原生近战伤害成功后接入，灵魂爆发应在自身伤害计算前清空。

不用固定起始五层代替状态；最多五层、200tick逐层衰减。原版隐藏状态链能保存每层和递减时钟，并在换层时同步，不需第二个永久计量。箭和戟在生成时读取真实施法者怒气，原生系数分别5%／10%；不能统一乘近战20%，也不能在Ars增强之后再次放大。

Phantom Arrow继承AbstractArrow，必须禁止玩家构造器默认的ALLOWED拾取。特殊Ars形态还需运行原生子类tick保存拖尾，抑制原生运动，重复方块命中后解除inGround而不是永久淡出。原生箭的伤害类型穿透hurt冷却；“第二下也成功”不能按其他弹体的无敌帧失败规则断言。单戟是地面Entity，不是飞行长枪；原生事件4、state1–4、延迟攻击及消退保留，服务器才读取Core上下文。

本轮首跑5/6通过：衰减检查用了未加入PlayerList的伪ServerPlayer，它不走实际连接的doTick。用真实已生成生物验证自然状态tick后6/6通过；持久化和整段隐藏链递减另做检查。不得为测试伪玩家缺少tick修改业务状态逻辑。客户端未人工验证。


## dev.47：原生阵列与共享锚点

咒翼第二批调用本体私有布阵和完整Goal／aiStep，不复制螺旋、环形、扇形的实现。把未加入世界的候选预先分阶段收集，可判断无有效地面退款，也避免第一圈缺地面但第二圈可用时错误拒绝。原生幻影戟仍继承真实owner、一次增强和原生伤害／怒气系数；只通过场景条件选择能生效的落点，不强行补数量。

身体行动共用ExecutionAnchor与ActionGeometry，不另写自身／友军／位置伤害流程。怒气必须实时读取同一个逻辑施法者状态；原生setRageMeter增层接到该状态，满层时原生不再调用setter但成功伤害仍应刷新衰减，需补这条边界。灵魂爆发清空发生在打击而非启动，且自身不再加层。面积效果不声明body claim，身体被替换不能误取消并行爆发。

新增AnimationState家族时，同时扩展协议白名单、服务端snapshot、客户端proxy、动画key／武器形态和独立client开关，并更新专用服务器的全状态往返测试。Maledictus getAnimationState使用字符串identity，客户端使用原生字面量radagon／mass_effect，并显式启动状态时钟，视觉proxy不tick AI。

测试不能在戟浪已开始接触后用总掉血断言第二次近战朝向，也不能把方块角点当作中心推断无落点。真实ServerPlayer友军可检查self包，伪payer未建立追踪时tracking-only包为空不等于客户端缺失。异步断言失败必须即时清理夹具，实体查询按真实owner过滤，避免泄漏造成下一批计数失败。


## dev.48：原生状态 Goal 与完整动作

InternalAttackGoal与InternalStateGoal的start不能视为等价入口：后者假定状态已由上一动作进入。独立调用状态型动作必须明确进入初始状态，否则可能收费但没有伤害和有效幻影包。服务端检查要同时确认实际伤害、动画包和动作结束，不止Mana扣除。

读取原生goal状态/持续时间替代匿名类序号；普通共用接口放casting包，不能放Mixin专属包，否则可能在注册实体时类加载失败。新增namespace要有实际GameTest模板；用根任务:runGameTestServer，避免顺带运行Core子项目的不同测试。

位置动作可以使用未注册帧的碰撞/简化运动，实体动作把原生冲量作用于实际actor，两者调用同一攻击Goal。不要用升空超时伪造落地；原生goal.lookAt与ActionGeometry不能同时拥有朝向控制，否则冲量和可见攻击朝向可能不一致。子箭与原生可视地面碎块也要随根清理，不能只管理主要伤害载荷。地面波不自动积攒怒气，不能因扩展满层刷新入口就改变原生状态规则。

新增获取预算用九拆咒魂碎片，保留旧配方，13魔符实际9锭覆盖三次保底击杀。资源只引用；依赖真实实体ID的AfterImage未伪造ID，记录翼焰替代尾迹和位置运动近似。15项服务端检查通过，客户端仍待人工确认。

## dev.52：动作模型不等于完整动作特效

焰魔原生 renderer 只更新剑尖 socket；火焰拖尾由实体 tick 里的纯视觉 SwingParticles 调用产生。视觉代理不 tick 时必须单独接这个方法，先渲染采样、再调用粒子，并按变化的逻辑 tick 去重。新动作、阶段切换、遮挡后重见、丢包或瞬移后先初始化旧剑尖，避免从零坐标／远处拉出海量粒子。强化砸击的准备／收招和剑舞结尾还有其他私有纯视觉方法，不能只看 server aiStep。

咒翼的旋斩光环与电弧已经在原生渲染层，但模型统一压到第一人称 10% 会把它们一起压暗。身体透明度和动作粒子／电弧透明度应分开；短暂残像继续淡化，避免叠出高亮光团。原生 AfterImage 依赖真实实体 ID，无世界实体的代理可复用现有 native renderer 画短寿命历史姿态，不得捏造注册 ID 或用整只 Boss tick 换取特效。实际发布包中的 Ignis SwingParticle 是空方法，检查调用名之后还要检查实现，不能凭名字声称缺了独立刀光。具体行为和人工验证缺口见 action-visuals-dev52.md。

## dev.53：调用帧的来源 ID 与实体音效

Native Goal 使用无世界 Boss 帧构造子光束后，重绑 `beam.caster` 还不够，必须同步更新 native caster ID；真实执行者 ID 另行保留，不能把友军、付款者和伤害拥有者混成一个。原生 `Level.playSound(player, entity, ...)` 会发送绑定实体 ID 的声音包，无世界帧不会在客户端出现。只对本附属帧把声音改为实际锚点的位置调用，保留原声与参数；不要同时补播一份而保留可解析的重复声音。可用 NeoForge 的 PlayLevelSoundEvent 同时验证位置、数量与事件类型，不依赖伪玩家是否出现在 PlayerList。

利维坦灵珠 12／24 阵调用原生 aiStep 的实际布阵片段，不复制方向表；三连调用已注册 native Goal，并复用单束 driver。延长时效后不同束可能重叠，各束必须保留自己的锁定方向；任一束未付费时取消整组排队输出，不能回蓝后再次凭旧会话发射。细节与验证见 leviathan-volleys-dev53.md。


## dev.54：远古遗魂的运动来源与视觉入口

原生 Sandstorm 的轨道采样按 caster 类型分支，玩家瓶中沙暴半径6、Boss半径8，且不能直接支持其他友军或固定点。只在 updateMotion 临时提供脱离世界的原生Boss帧作为中心，伤害仍保留真实owner，避免为了几何改动伤害身份。延长寿命后原生295tick出生动画门槛也要同步调整。

EarthQuake 的 tick 在 super.tick 前还有一次 move 和接触／粒子调用，单纯抑制 ThrowableProjectile.tick 不能完成特殊轨迹适配。需要保留视觉tick但阻止前置move、免费伤害和原生60tick到期；触发时再调用原生接触，走伤害成功续接。普通地震波的重复伤害不能反复执行同一实体的后续编排。

StompParticle 只在客户端分支执行，Stompsound 用 playLocalSound；无世界帧没有客户端实体tick，必须分别桥接原生粒子参数与服务端位置声音。不能只验证翻起的地块就宣称全部特效齐全。具体实装及8项服务端验证见 remnant-first-dev54.md，客户端外观未人工确认。


## dev.55：自定义弹射物基类与多次命中

Cursed Sandstorm 的 tick 在具体类内调用 CustomAbstractHurtingProjectile.tick 执行原生碰撞／加速，再更新追踪和寿命。只在具体类压制位移仍会留下基类碰撞，特殊Ars轨迹须覆盖基类碰撞，并保留原生具体类粒子与同步。普通弹有两个成功命中次数，不应在第一次命中就关闭会话；重复形态则每触发付款并复位原生预算，不能被290tick寿命／消退状态偷偷永久禁用。

新增原生幻影家族同时更新 Kind 的所有 exhaustive switch、snapshot、客户端proxy、配置和全状态协议夹具。Ancient Remnant 的三连尾砸使用 ground_tail，不能仅看 threetailhit 字段名推断动画key。调用帧的 roar 粒子／实体音效与地裂一样需要独立服务端发送；具体实现和9项验证见 remnant-second-dev55.md。


## dev.56：原生冲撞的碰撞与伤害几何、双踩的最后两tick

原生冲撞的接触伤害只查询Boss自身包围盒，不能直接让它永远沿用玩家的小包围盒，否则与幻影范围和高速移动不符。仅在原生伤害调用期间使用Boss尺寸，真实执行者／脱离实体的位置帧仍用实际碰撞尺寸移动。移动冲撞的位置帧不能每tick重新吸回最初锚点；用同一driver维持位置、重力和碰墙，保留逻辑caster作为付款者与伤害来源。原生 ChargeBlockBreaking 只为本附属SpellRemnant取消，真实Boss保持原样。

原生state13第二次践踏从50tick开始，一直推进到68tick，但注册Goal的时长仅66tick。独立范围效果须调用完整aiStep到68并留出地块退场时间，不能机械按Goal时间截掉最后一圈。半血按原施法者判断，友军生命不改变变体；不新增魔符或额外收费。具体交付见 remnant-actions-dev56.md。

## dev.57：炽燃遗魂的粒子实体与原生骨弹

灰烬吐息的主体是原生Ashen_Breath实体客户端tick产生的80烟／2火焰粒子，不是需要另接的模型。让真实实体出生，并同步管理标记／寿命，服务端只由会话tick一次；不能像未出生的Boss调用帧那样仅运行服务端就宣称有特效。它的tick会读取caster.yHeadRot，友军或固定点执行时须用实际执行方向，不能跟着付款者转。

Blazing Bone本身没有独立尾迹／额外点燃；旋转来自原生物品渲染器，碎裂来自实体事件3。重复Ars载体应保留该事件，仅抑制其原生discard；ThrowableProjectile既有轨迹钩子负责禁止双重重力／碰撞，普通弹继续走原生轨迹。骨骸风暴直接调用注册Goal的四次随机6／8／10发，不复制原生方向表，子弹与独立单弹共用伤害桥接但不独立收费。详见 revenant-dev57.md。
