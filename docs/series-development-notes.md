## 新 agent 必须获得的判断依据

- 原模组完整实现优先于只复刻一次伤害。查服务端入口，同时查同步、实体事件、渲染器、粒子、声音、命中后子效果与结束过程。
- 同类能力优先 Boss 版本；没有物品施法来源时可以采用 Boss 直接掉落物制作。不要机械地把只适合 Boss 身体的动作、防护或地形破坏全部做成魔符。
- 区分施法者、执行者、受益目标和付款者。友军执行冲锋并不意味着由友军支付；所有者/伤害归属用 Core 上下文，友军用 Core API。
- 原生轨迹和 Ars 轨迹只保留一个运动驱动者。普通、持续/重复载荷分别检查命中次数、费用和接续次数；子攻击属于已付费用时不要再次收费，也不要各自复制整段 Ars 后续效果。
- 临时修改世界必须覆盖自然结束、所有者离开、区块卸载、重启及位置被替换；不能只在实体正常死亡时清理。
- 新状态能力说明清楚默认时长、修饰公式、上限和保护范围。不要给共享形态写某一种载荷专用的增强说明。
- 图标父模型可能是 builtin/entity，必须检查真实物品身份和原生渲染入口。文本要核对 Ars 实际使用的 glyph_name 与增强说明键。
- 费用结合命中覆盖、持续攻击、控制及组合能力评估；Iron 的对照等级不能始终假定为 1。参考相邻 Ars-Balance-Baselines 的当前记录，尚未实际测到的数据应标为估算。
- 收拢修改后做必要验证。GameTest 不能证明客户端画面完整；既有成功记录不能替代新代码的检查。固定 Core 副本不改，公共修复另开明确的 Core 任务。
