# 身体行动打断

dev.36 将当前灾变身体行动选择接入 Conflux0.1.21 `startReplacing`：焰魔剑舞及四种动作、斯库拉重击连段／旋转／钩锚跃落、先驱者冲锋、末影守卫重拳／上勾拳／瞬移重击／跳劈／火箭拳、巨兽肩撞。没有将召唤、弹射物、火场或共享引导改成全局互斥。

## 交接

新行动先检查原有选点与设备条件：有效实体、授权、骑乘、范围、加载区域、锚点表面或传送空间等。原费用事务在实际调用效果前预留资源。只有能进入新的执行会话时，Core才清理实际actor的冲突声明；付款者和其他actor的动作不因此停止。位置动作没有实体声明，不替换实体动作。

旧动作使用既有取消清理，包括关闭幻影、撤去冲量／动作锁、恢复重力，以及焰魔调用帧拥有的子攻击。已经付过的旧费用不退，新动作独立计费，原主动冷却与创造规则保留。同一个Ars编排的效果按原生顺序执行；连续身体动作会以后触发者为准，成功触发过的各段分别付费，没有增加排队或自动连段。

重力初值移到新driver.start，在旧close之后读取；不能在准备新会话时记录旧动作暂时设置的noGravity。驱动close加启动标记，未取得状态的准备对象不会解除其他会话锁或衰减执行者速度。巨兽肩撞新增明确独占ENTITY_ACTION声明，不再用旧“活动”标记表达身体动作。

通用Core入口是显式opt-in，普通start继续拒绝冲突。Core没有灾变类型引用；旧occupiesCaster映射独立ACTIVITY，避免旧持续活动被误判为身体动作。新启动异常仍清理自己的声明并由资源事务撤销费用，不尝试逆向恢复已清理的旧原生动画。

## 施法入口

Iron0.17.18绑定武器忽略“只有独占ENTITY_ACTION”的忙碌状态，以便进入新效果。吟唱、CHANNELING及ACTIVITY等其他占用仍保持原先的入口限制。本改动不是将所有Iron持续施法改为打断；也没有增加灾变到Iron的硬依赖。

## 验证范围

针对性套件 `-PgameTestNamespaces=cataclysm_nouveau_interrupt -PwithIron=true`包含已有身体动作与锚点回归、新跨系列切换／拒绝无效目标／重力恢复，以及通过反射调用真实Iron绑定API释放Ars编排的可选共存用例。测试专用依赖在忽略的libs/iron-coexistence，发行包不携带这些JAR。

新跨系列用例让一个友军按顺序执行强化跃砸→跃砸→剑舞→旋转→重击连段→先驱者冲锋→重拳→上勾拳→火箭拳→肩撞；断言只有最新actor状态保留、每次收费一次、旧焰魔子攻击消失、共享引导与其他友军行动保留。缺少钩锚表面／传送目标、敌方执行者或资源不足不得打断旧行动。

斯库拉和末影守卫的完整锚点／位置／幻影迁移仍是后续工作；这里保留各自历史选点与动作语义，只改交接和状态所有权。未开图形客户端，快速切换时的幻影淡出与新动画混合需人工观察。
