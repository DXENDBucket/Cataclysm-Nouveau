# 身体行动的位置锚点（dev.38）

## 用户问题与修正

dev.37只补了实体执行时的幻影。部分旧入口拒绝方块目标，另一些把方块命中解释成施法者的移动方向；因此不能像焰魔那样在一个位置、以触发方向执行。

现将同一批十种身体行动接入Conflux已有的`ExecutionAnchor.beneficial`固定位置入口：斯库拉雷电重击连段/旋转挥锚/钩锚跃落；先驱者冲锋撞击；末影守卫引力重拳/上勾连段/闪现突袭/空降重砸/火箭拳；巨兽肩撞。原实体执行路径保留。

## 行为

- 方块命中位置就是固定攻击原点，使用触发携带的入射方向；未携带有效方向时按触发时施法者朝向。地面体术沿水平朝向，保持焰魔固定动作的处理方式。
- 位置和朝向在启动时冻结，施法者之后移动或转向不会搬走攻击或幻影。施法者、付款者与伤害拥有者继续使用原施法上下文，不伪造一个执行者。
- 保留原生攻击、阶段、半血条件、费用与冷却。移动不适用于固定位置：肩撞/冲锋在该点执行原生碰撞攻击；闪现不传送施法者；钩锚跃落完成原生准备后在该点执行落地打击，不抛锚或拉动身体；空降在固定点进入原生落地阶段。
- 固定动作不持有实体身体声明，不打断施法者现有身体动作；多个位置动作各自独立。仍按每次成功触发收费，不自动合并多次施法。
- 不强行提供位置版持续增益：水面行走等状态效果仍需要实体。未新增魔符或Boss能力。
- 无效/未加载位置失败且不收费，不加载新区域。施法者失效、离开维度、权限/区域失效或自然结束由Core执行会话清理。

## 服务端与客户端

新`PositionBodyActions`只运行脱离世界的原生调用帧、目标标记、原生攻击Goal和已有子攻击适配。它们不作为实体加入世界。调用前后将攻击帧固定在锚点，阻止原生冲量或传送带走位置；原实体模式的传送事件与安全落点检查保留。

`BodyPhantomPayload`协议从1提升到2，新增`positionAnchored`；固定点的实体ID为-1、UUID为零。客户端位置幻影直接使用同步位置，无需找到执行实体。包按同一维度附近玩家发送，并补发给付款玩家；不再用付款者替代空执行者。原生状态/动画、阶段重置、结束淡出及客户端系列开关继续沿用。

固定Core SHA：`030880436d93ae104d6e14ba0240b6b1ba698513`（0.1.21）。未修改Core或其他附属。实际依赖为NeoForge1.21.1/21.1.250、灾变3.33、JDK21。仍只有NeoForge版。

## 验证

`cataclysm_nouveau_positions`集中17/17通过，最终build与二进制/源码包`verifyDistributions`通过。十个真实位置动作均验证伤害确实发生在远处、保护友军、归属原施法者、一次收费、包内锚点/方向冻结、原施法者位置/运动/重力不变、自然结束与协议往返。额外验证固定位置与实体共存、无效位置不影响现有动作、原生实体闪现/空降/打断、原焰魔位置能力及旧实体视觉协议。

没有客户端人工画面验证。服务器测试不等于实际透明模型、方向与动作手感已验收。
